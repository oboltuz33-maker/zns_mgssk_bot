# ZNS — Mini App ДОСААФ МГССК

Telegram Mini App для заявок на перевозку оружия к соревнованиям. Перевозчики клуба выбирают соревнование,
участников и их оружие, вид транспорта — и заявка появляется строкой в Google Таблице, где её обрабатывает
оформитель. Бот сообщает о новых соревнованиях, о подтверждении доступа и о смене статуса заявки.

## Как устроено

```
Telegram ── Mini App (React, GitHub Pages) ──HTTP──► Apps Script (веб-приложение) ──► Google Таблица
   ▲                                                       │
   └──────────────── сообщения бота (Bot API) ◄─────────────┘   ◄── триггер onSheetEdit на ручные правки
```

- **Приложение** (`src/`) — статический сайт на GitHub Pages. Данных не хранит: листы получает от Apps Script
  одним запросом и держит копию на устройстве (`localStorage`), чтобы открываться сразу.
- **Apps Script** (`apps-script/sheets.gs`) — единственный бэкенд. Проверяет подпись Telegram (`initData`) токеном
  бота, решает, кому что можно, читает и пишет листы, шлёт сообщения бота. Привязан к таблице.
- **Google Таблица** — данные и рабочее место администратора и оформителя.

Доступ: пользователь Telegram привязывается к строке листа «Спортсмены» по номеру телефона (подписанный ответ
`requestContact`). Данные получают только спортсмены со статусом «Подтвержден»; заявки создают только перевозчики
(«Перевозчик» = «Да»), каждый видит только свои. Все проверки — в Apps Script, приложение лишь повторяет их для удобства.

## Окружения

Рабочее и тестовое окружения полностью разделены: у каждого своя таблица, свой бот и свой Apps Script.
Код один и тот же — различаются только настройки.

| | Рабочее | Тестовое | Разработка |
| --- | --- | --- | --- |
| Настройки приложения | `.env.production` | `.env.test` | `.env.development` |
| Адрес | `…/zns_mgssk_bot/` | `…/zns_mgssk_bot/test/` | `npm run dev` |
| Сборка и выкладка | `npm run deploy` | `npm run deploy:test` | — |

В `.env.*`: `VITE_GOOGLE_SCRIPT_URL` — адрес развёртывания Apps Script, `VITE_BASE` — путь на GitHub Pages,
`VITE_ENV_LABEL` — метка окружения в приложении (пусто — рабочее).

Данные загружаются только в Telegram — вне его нет подписанных данных пользователя. Чтобы посмотреть dev-сервер
с данными, откройте его (например, через туннель) из тестового бота.

## Команды

```sh
npm install
npm run dev          # сервер разработки
npm run check        # линтер + тесты + сборка — перед коммитом
npm test             # только тесты (npm run test:watch — с перезапуском при изменениях)
npm run deploy:test  # проверка, сборка и выкладка тестового окружения на GitHub Pages
npm run deploy       # то же для рабочего
```

`deploy` и `deploy:test` сначала запускают линтер и тесты — с ошибками выкладка не начнётся. На GitHub те же
проверки идут при каждом push (`.github/workflows/check.yml`).

## Выкладка Apps Script

Скрипт пока выкладывается вручную:

1. Скопировать `apps-script/sheets.gs` в редактор Apps Script таблицы нужного окружения (Расширения → Apps Script).
2. «Развернуть» → «Управление развёртываниями» → карандаш у текущего развёртывания → версия «Новая версия» →
   «Развернуть». Адрес развёртывания при этом не меняется, `.env` трогать не нужно.

Если в новой версии скрипт обращается к новому сервису Google (так было с Диском для резервных копий), после шага 1
запустить в редакторе `installTriggers` и разрешить доступ — и только потом шаг 2: без разрешения владельца
развёртывание отвечает ошибкой.

Сначала — в тестовом окружении. **Скрипт выкладывается раньше приложения**: новое приложение может пользоваться
действиями, которых нет в старом скрипте (так было с загрузкой листов через POST). Новый скрипт поддерживает и
прежние версии приложения, пока они остаются в кэше телефонов.

## Настройка нового окружения

Окружение связывают четыре значения. Каждое следующее зависит от предыдущего, поэтому порядок шагов важен:

| Значение | Откуда берётся | Где указывается | Что сломается, если не совпадёт |
| --- | --- | --- | --- |
| Токен бота | @BotFather → `/newbot` | Свойство скрипта `BOT_TOKEN` | Подпись Telegram не сходится — «Не удалось подтвердить пользователя Telegram»; сообщения не уходят |
| Адрес развёртывания Apps Script (`https://script.google.com/macros/s/<ID развёртывания>/exec`) | «Развернуть» → «Новое развёртывание» | `VITE_GOOGLE_SCRIPT_URL` в `.env.<окружение>` (вшивается в сборку) | Приложение ходит в чужую таблицу или получает ошибку |
| Адрес приложения (`https://oboltuz33-maker.github.io` + `VITE_BASE`) | Путь `VITE_BASE` в `.env.<окружение>` | Свойство скрипта `MINI_APP_URL`; @BotFather → Configure Mini App | Бот открывает приложение другого окружения |
| Бот, из которого открыто приложение | — | — | Приложение должно открываться из бота, чей токен в `BOT_TOKEN` *того же* скрипта, иначе подпись не сходится |

Порядок (функции запускаются в редакторе Apps Script: выбрать в списке над кодом → «Выполнить»; вывод — в
«Журнале выполнения»; при первом запуске Google попросит доступ):

1. **Бот.** @BotFather → `/newbot` → сохранить токен. Токен — секрет: только в свойствах скрипта, не в репозитории.
2. **Таблица.** Копия рабочей таблицы (Файл → Создать копию). Скрипт копируется вместе с ней, но развёртывания,
   свойства и триггеры — нет. Если копируется рабочая — очистить в «Спортсменах» столбец ChatId и лишние заявки.
3. **Скрипт.** Расширения → Apps Script → вставить актуальный `apps-script/sheets.gs`.
   «Настройки проекта» (⚙️): часовой пояс — Europe/Moscow; «Свойства скрипта»:
   - `BOT_TOKEN` — токен из шага 1;
   - `MINI_APP_URL` — адрес приложения этого окружения (рабочее: `…github.io/zns_mgssk_bot/`, тестовое:
     `…github.io/zns_mgssk_bot/test/`). Адрес известен заранее по `VITE_BASE`, приложение для этого выкладывать не нужно.
4. **Триггеры.** `installTriggers` (правки таблицы, ночной перенос заявок в архив и резервная копия; при первом
   запуске Google попросит доступ к Диску — для копий). Если в «Соревнованиях» уже
   есть строки — `markExistingCompetitions`, иначе первая правка разошлёт старые соревнования как новые.
5. **Развёртывание.** «Развернуть» → «Новое развёртывание» → тип «Веб-приложение», «Выполнять как: я»,
   «У кого есть доступ: все» → скопировать адрес `…/exec` (не `…/dev` — тот работает только для владельца).
   Новое развёртывание делается **один раз**: дальше код обновляется новой версией того же развёртывания
   (см. «Выкладка Apps Script»), и адрес не меняется. Новое развёртывание — новый адрес, и тогда шаги 6–7 заново.
6. **Приложение.** Вписать адрес из шага 5 в `VITE_GOOGLE_SCRIPT_URL` файла `.env.<окружение>` (для тестового
   его же — в `.env.development`), проверить `VITE_BASE` и `VITE_ENV_LABEL`. Выложить: `npm run deploy:test`
   или `npm run deploy`. При самой первой выкладке в репозитории: Settings → Pages → Deploy from a branch → `gh-pages`.
7. **Кнопки бота.** У бота две кнопки, адрес задаётся в каждой отдельно:
   - кнопка меню слева от поля ввода — `setupMenuButton` (ставит `MINI_APP_URL`);
   - стартовая кнопка и ссылка `t.me/<бот>?startapp` (Main Mini App) — только в @BotFather: выбрать бота →
     Bot Settings → Configure Mini App → Enable Mini App / Edit Mini App URL → адрес приложения.
8. **Проверка.** `checkSetup`: бот совпадает с ожидаемым, вебхук «не задан» (если задан — `removeWebhook`),
   кнопка меню ведёт на `MINI_APP_URL`, адрес веб-приложения совпадает с `VITE_GOOGLE_SCRIPT_URL`, триггеры есть.
   Затем открыть бота в Telegram → «Приложение» → войти по телефону (спортсмен должен быть в «Спортсменах»
   со статусом «Подтвержден»).

Что менять при смене одного значения:

- **Новый токен** (`/revoke` в @BotFather) — только `BOT_TOKEN`. Кнопки и адреса остаются.
- **Новое развёртывание Apps Script** — `.env.<окружение>` и пересборка приложения (шаг 6).
- **Новый адрес приложения** (`VITE_BASE`) — пересборка, `MINI_APP_URL`, `setupMenuButton` и @BotFather (шаги 3, 6, 7).

## Таблица

Первая строка листа — заголовки, первый столбец — ID строки; строки с пустым первым столбцом игнорируются.
На листах «Спортсмены», «Соревнования» и «Оружие» строкам, внесённым вручную, ID выдаёт триггер. Исключения:
в «Заявках» первый столбец — № заявки (ставит скрипт), в «Спортсмен/Оружие» — ID спортсмена, в «Видах
транспорта» — название. Столбцы ищутся по заголовкам, порядок не важен. Названия — в начале `sheets.gs`.

| Лист | Что в нём |
| --- | --- |
| Спортсмены | ФИО, телефон, ChatId (заполняет скрипт при входе), статус, «Перевозчик», «Администратор», настройки уведомлений |
| Соревнования | Название, № ЕКП, вид, даты, адрес, «Рассылка» (отметка о рассылке перевозчикам) |
| Оружие | Название, номер |
| Спортсмен/Оружие | Какое оружие за кем закреплено |
| Виды транспорта | Справочник: первый столбец — название |
| Заявки | Одна строка на заявку; № и текст собирает скрипт, статус меняет оформитель |
| Архив заявок | Удалённые автором (статус «Удалена»), заявки прошедших соревнований и удалённых спортсменов (с прежним статусом) |
| _Журнал | События: входы, заявки, рассылки, ошибки доставки, лимиты Google. Создаётся сам |

Статусы заявки: «Новая» (автор может изменить или удалить) → «В работе» → «Выполнена»; «Отклонена» — из «Новой»
или «В работе», с причиной в столбце «Причина отклонения» (отклонённую можно снова взять в работу). О смене на
«В работе», «Выполнена» и «Отклонена» бот сообщает автору. «Удалена» — скрипт при удалении автором.

Перенос в архив: раз в сутки (в 3 часа ночи, функция `archivePastApplications`, триггер ставит `installTriggers`)
заявки, у которых прошёл последний день соревнования по ЕКП, переносятся в «Архив заявок» в любом статусе — статус
сохраняется. Заявки без даты по ЕКП остаются в «Заявках». Соревнования не переносятся.

## Резервные копии

Каждую ночь в 2:00 (функция `backupSpreadsheet`, триггер ставит `installTriggers`) таблица копируется в новую Google
Таблицу в папке «Резервные копии — <название таблицы>» на Диске владельца скрипта: все листы со значениями, формулами
и оформлением, без скрипта и токена бота. Хранятся копии за 30 дней и первая копия каждого месяца — 12 месяцев,
остальные уходят в корзину Диска. У каждого окружения своя папка (её ID — свойство скрипта `BACKUP_FOLDER_ID`).
В копиях персональные данные — папку никому не открывать и других таблиц в неё не класть.

Контроль: копия и сбой пишутся в «_Журнал»; при сбое бот пишет подтверждённым администраторам, а Google — письмо
владельцу. `checkSetup` показывает, когда сделана последняя копия (⚠ — старше двух суток).

**Восстановление** (вручную, в редакторе Apps Script):

1. `listBackups` — список копий с ID. Нужную копию можно открыть и посмотреть — это обычная таблица.
2. В разделе «Резервные копии» `sheets.gs` заполнить `RESTORE`: `backupId` — ID копии; `sheets` — какие листы
   (пусто — все, кроме служебных «_…»); `ids` — только строки с этими ID на одном листе (например, удалённый
   спортсмен), остальные строки не трогаются.
3. `restoreCheck` — отчёт: сколько строк будет заменено, каких столбцов нет в копии или в таблице. Ничего не меняет.
4. `restoreApply` — в течение 30 минут после проверки, не меняя `RESTORE`. Сначала сохраняется копия текущего
   состояния («перед восстановлением») — неудачное восстановление откатывается ею же. Затем строки заменяются,
   кэш приложения сбрасывается, уведомлений о восстановленных статусах не будет.
5. Очистить `RESTORE`.

Подойдёт и таблица не из папки копий — например, файл .xlsx, загруженный на Диск и сохранённый как Google Таблица.

**Изменение структуры таблицы.** Восстановление сопоставляет столбцы копии с таблицей по заголовкам, поэтому старые
копии остаются пригодными, если соблюдать два правила:

- переименовали лист или столбец — добавить строку «старое → новое» в `RENAMED_SHEETS` / `RENAMED_COLUMNS`
  (`sheets.gs`, раздел «Резервные копии») и не удалять её;
- новый столбец должен работать с пустым значением: у строк из старых копий он будет пустым.

Порядок столбцов значения не имеет; данные удалённых столбцов не восстанавливаются (отчёт `restoreCheck` их называет).

## Лимиты Google

Остаток дневных лимитов Apps Script Google не показывает — только ошибку, когда лимит кончился. Лимиты — на аккаунт
владельца скрипта, общие для всех его скриптов. Сигналы — в «_Журнал»:

- «Лимит Google исчерпан» — ошибка лимита (запрос приложения, правка таблицы, рассылка); одна и та же — раз в час;
- «Лимит близко» — запросов к Telegram за сутки 70% и 90% лимита (по счётчику самого скрипта — приблизительно).

`checkSetup` показывает запас: запросы к Telegram за сегодня, размер свойств скрипта, размер копий листов для кэша
(лист больше предела читается из таблицы при каждой загрузке приложения), число ячеек таблицы. Лимиты — константы
в разделе «Лимиты Google» `sheets.gs` (значения для обычного аккаунта; у Google Workspace больше — поменяйте).
Подробно о каждом вызове — редактор Apps Script, «Выполнения».

## Табличный вид

Списки заявок, соревнований и спортсменов можно смотреть лентой карточек или таблицей (кнопка ☰ / ▦ рядом с поиском).
В таблице — сортировка нажатием на заголовок, на телефоне часть столбцов скрыта, нажатие на строку открывает карточку.
Выбор вида и сортировки запоминается на устройстве для каждого списка. Подробности — `TABLE_VIEW_PLAN.md`.

## Администрирование

Спортсмен с «Да» в столбце «Администратор» листа «Спортсмены» видит в приложении раздел «Админ» и получает
данные целиком (все заявки, все соревнования, все столбцы спортсменов). Там:
- заявки — смена статуса по порядку жизненного цикла, отклонение с причиной, правка заявки (выгрузка в Excel готова,
  но пока скрыта — `SHOW_EXCEL_EXPORT` в `src/config.js`);
- спортсмены — подтверждение, правка (кроме телефона и ChatId), удаление (закрепления удаляются, заявки — в архив),
  закреплённое оружие;
- соревнования — создание и правка, рассылка перевозчикам по тем же правилам, что у триггера;
- оружие — справочник (пара «Название + Номер» уникальна), удаление вместе с закреплениями.

Подробности и принятые решения — в `ADMIN_PLAN.md`.

## Тесты

`npm test` — vitest. `tests/client.test.js` проверяет модель данных, черновик заявки, поиск и правки данных
на месте. `tests/apps-script.test.js` запускает настоящий `sheets.gs` с подставными сервисами Google
(`tests/gas.js`: таблица в памяти, кэш, свойства, подпись Telegram настоящим HMAC) и проверяет `doGet`, `doPost`
и `onSheetEdit`: доступ, отдачу листов, создание, изменение и удаление заявок, вход по телефону и по ФИО,
уведомления, резервные копии и восстановление.
