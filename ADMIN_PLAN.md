# Администрирование в приложении — план

Администратор (обычно он же оформитель) — подтверждённый спортсмен с «Да» в столбце «Администратор» листа
«Спортсмены». Администраторов может быть несколько. Работа напрямую с таблицей остаётся; приложение упрощает
частые операции и защищает таблицу от ошибок ручного ввода.

Когда этап сделан — отметить его здесь; когда сделан весь план — перенести суть в README и удалить файл.

## Общие правила

- Права проверяет Apps Script на каждом действии (как «Перевозчик»); приложение лишь прячет недоступное.
- Администратору отдаются полные данные: все столбцы «Спортсменов», все заявки, все соревнования основного листа
  (и прошедшие). Остальным — как раньше.
- Каждое действие — запись в «_Журнал» (кто и что изменил). Перед записью строка перечитывается: если её
  одновременно правят в таблице, действие не выполняется. Значения защищены от формул (`safeCell_`).
- Уведомления бота: записи скрипта не запускают триггер `onSheetEdit`, поэтому действие из приложения само
  вызывает ту же логику уведомлений, что и триггер, с той же памятью «о чём уже сообщено» — без дублей.
- Порядок выкладки прежний: сначала Apps Script, потом приложение; сначала тестовое окружение.
- Перед выкладкой этапов 0–1 добавить в таблицу столбцы «Администратор» («Спортсмены») и «Причина отклонения»
  («Заявки» и «Архив заявок» — чтобы причина переносилась в архив).

## Этап 0. Основа — сделано

- Столбец «Администратор» в «Спортсменах»: значения «Да» / «Нет» (пусто — как «Нет»); `requireAdmin_` в скрипте.
- Полные данные для администратора при загрузке листов.
- Раздел «Администрирование» в нижнем меню — только у администраторов.

## Этап 1. Заявки — сделано

- Список всех заявок: фильтр по статусу, поиск, период по срокам ЕКП.
- Статусы — только по порядку жизненного цикла, откатов в приложении нет (только в таблице):
  `Новая → В работе → Выполнена`; `Новая → Отклонена`; `В работе → Отклонена`; `Отклонена → В работе`.
  Заявки прошедших соревнований раз в сутки уходят в «Архив заявок» с прежним статусом (`archivePastApplications`).
- «Отклонена» — с обязательной причиной в новом столбце «Причина отклонения»; автору — сообщение бота с причиной.
  Взятие отклонённой в работу очищает причину.
- Редактирование — структурно, как в мастере: участники и оружие, транспорт, соревнование (его поля
  подставляются из справочника; можно оставить как есть, если соревнования уже нет в списке), сроки перевозки,
  адрес. ФИО (автор, CreatedBy) не меняется. Удаления нет.
- Правка соревнования поданные заявки не трогает: администратор сначала исправляет соревнование, затем
  при необходимости заявки (выбрав соревнование заново).
- Выгрузка в Excel (пока скрыта в приложении: `SHOW_EXCEL_EXPORT` в `src/config.js`; в Apps Script готова):
  лист «Заявки» с отбором по срокам ЕКП (пересечение с периодом), только основной лист
  (без архива), столбцы как в таблице с «№», без CreatedBy и CreatedAt. Файл .xlsx бот присылает в чат.

## Этап 2. Спортсмены — сделано

- Список «Требует подтверждения» с кнопкой «Подтвердить» (бот сообщает спортсмену, как сейчас).
- Редактирование всех полей, кроме ID и ChatId (телефон — без дублей). Статус — из списка: Подтвержден, Требует подтверждения,
  Добавлен вручную, Архив («Архив» = запрет работы, отдельной логики нет). Признак «Администратор» редактируется
  (записывается «Да» / «Нет», как «Перевозчик»), снять его с себя нельзя. При смене ФИО — проверка дублей (как при регистрации).
- Удаление: удаляются его закрепления оружия, его заявки переносятся в «Архив заявок» с прежним статусом.
  Чужие заявки, где он участник, не меняются (там текст).
- Создание: ФИО (без дублей), телефон (необязательный, без дублей), признаки и прочие столбцы; статус —
  «Добавлен вручную» (подтвердится сам при входе по номеру). После создания открывается закреплённое оружие.

## Этап 3. Соревнования — сделано

- Создание, просмотр, редактирование (без удаления). «Вид соревнования» — свободный текст.
- Рассылка перевозчикам — той же функцией, что у триггера (условие и отметка «Рассылка» общие).

## Этап 4. Оружие — сделано

- Справочник: создание, редактирование, удаление. Номер не уникален — уникальна пара «Название + Номер»
  (без учёта регистра и лишних пробелов).
- Удаление единицы удаляет её закрепления; заявки не меняются (там текст).
- Закрепления: выбрать спортсмена → закрепить из справочника или открепить. Если единицы нет в справочнике —
  можно завести её здесь же после подтверждения «Такой единицы нет в справочнике. Добавить?».

## Как устроено в приложении

Раздел «🛠 Админ» (`src/pages/AdminPage.jsx`) — вкладки «Заявки», «Спортсмены», «Соревнования», «Оружие».
Формы открываются отдельными страницами без нижнего меню: `admin-application`, `admin-athlete`,
`admin-athlete-weapons` (закреплённое оружие спортсмена), `admin-competition`. Справочник оружия правится
прямо во вкладке. Запросы и проверки ввода — `src/data/admin.js`, действия Apps Script — раздел
«Администрирование» в `apps-script/sheets.gs`.
